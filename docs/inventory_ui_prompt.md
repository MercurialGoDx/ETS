# Задача: панель инвентаря по Tab

Unity 6000.0.58f2, URP. Проект — tower-defense/survivors: неподвижная башня в центре, волны врагов по кольцу, магазин по Q, боссы каждые 5 минут.

Нужно добавить панель, показывающую всё купленное за забег: оружие, улучшения и сводные характеристики. Открывается по Tab, рамка по центру экрана.

---

## Прежде чем писать код

Прочитай эти файлы — в них вся нужная механика:

- `Assets/Script/TowerAttack.cs` — хранит купленное оружие
- `Assets/Script/UpgradeManager.cs` — **класс внутри называется `UpgradesManager`**, с «s». Имя файла и имя класса не совпадают, не запутайся

- `Assets/Script/WeaponDefinition.cs`, `Assets/Script/UpgradeDefinition.cs` — ScriptableObject'ы контента

Скрипты UI лежат в `Assets/Script/UI/`.

## Часть 1. Доступ к данным (без этого панель показывать нечего)

### 1.1 Оружие

В `TowerAttack` список `weapons` — приватный `List<WeaponRuntime>`, где `WeaponRuntime` — приватный вложенный класс с полями `def` и `stacks`. Повторная покупка того же оружия увеличивает `stacks`, а не добавляет новую запись.

Добавь публичный доступ, не раскрывая `WeaponRuntime` наружу. Например:

```csharp
public readonly struct OwnedWeapon
{
    public readonly WeaponDefinition Def;
    public readonly int Stacks;
    public OwnedWeapon(WeaponDefinition def, int stacks) { Def = def; Stacks = stacks; }
}

public List<OwnedWeapon> GetOwnedWeapons() { ... }
```

Не отдавай наружу внутренний список напрямую — панель не должна иметь возможность его мутировать.

### 1.2 Улучшения

`UpgradesManager.ApplyUpgrade(UpgradeDefinition)` применяет эффект в скалярные поля и **сам объект нигде не сохраняет**. Купленные улучшения сейчас невозможно перечислить — это главная причина, по которой панель не сделать без правок.

Заведи в `UpgradesManager` словарь `Dictionary<UpgradeDefinition, int>` и инкрементируй его в самом начале `ApplyUpgrade`, до `switch` — тогда учтутся и покупки из магазина, и награды за боссов (`BossRewardUI.OnChosen` вызывает тот же метод). Отдавай наружу как `IReadOnlyDictionary`.

Важно: `ApplyUpgrade` в начале делает `if (upgrade == null) return;` — инкремент должен идти после этой проверки.

### 1.3 Поле тира

Ни в `WeaponDefinition`, ни в `UpgradeDefinition` нет поля тира — тир существует только как папка (`Assets/Prefab/Weapon/1Tier` … `4Tier`) и косвенно как цена. Цену использовать нельзя: у четырёх недоделанных оружий (`ChaosBounce`, `MagicBounce`, `Resonance`, `ChainLighting`) стоит заглушка `price = 10`, и они определятся как первый тир.

Добавь в оба SO:

```csharp
[Header("Тир")]
[Range(1, 4)] public int tier = 1;
```

Значение по умолчанию 1. Существующие ассеты не трогай — я проставлю тиры руками в инспекторе. Просто убедись, что панель корректно работает, когда у всего тир 1.

### 1.4 Геттер для золота

В `GoldManager` поле `goldGainBonus` приватное (`[SerializeField] private float`). Для панели статов нужен публичный `public float GoldGainBonus => goldGainBonus;` — только чтение, сеттер не добавляй.

## Часть 2. Рефакторинг слота

`ShopSlot` реализует `IPointerClickHandler`, `IPointerEnterHandler`, `IPointerExitHandler` и умеет: иконку, текст цены, показ тултипа по ховеру, покупку по клику. Инвентарный слот — это то же самое минус покупка, плюс счётчик стеков и цветная рамка по тиру.

Вынеси общее в базовый класс `ItemSlotBase` (`Assets/Script/UI/ItemSlotBase.cs`):

- поля `iconImage`, ссылки на текущий `WeaponDefinition` / `UpgradeDefinition`
- `OnPointerEnter` / `OnPointerExit` с показом и скрытием тултипа
- виртуальный `OnPointerClick`, по умолчанию пустой

`ShopSlot` наследуется и добавляет цену с покупкой. `InventorySlot` наследуется и добавляет счётчик и рамку.

**Осторожно:** `ShopSlot` уже расставлен по десяти объектам в сцене `Assets/Scenes/SampleScene.unity` с заполненными `[SerializeField]`-ссылками (`iconImage`, `priceText`). Если поля переедут в базовый класс с тем же именем и типом, сериализация переживёт переезд. Если переименуешь — ссылки в сцене обнулятся молча, и магазин перестанет показывать иконки. Имена полей не меняй.

## Часть 3. Панель

### Поведение

- Клавиша Tab открывает и закрывает. По образцу `ShopManager`, где `toggleShopKey` — публичное поле типа `KeyCode`, сделай так же настраиваемым, не хардкодь.
- **Время не останавливай.** Магазин по Q не паузит игру, инвентарь должен вести себя так же. Не трогай `Time.timeScale` — иначе появится стратегия «висеть в инвентаре, пока думаешь», а весь темп забега держится на таймере волн. (`BossRewardUI` паузит намеренно — это модалка с выбором, у неё другая роль.)
- При открытии панель перечитывает данные заново; живой подписки на изменения не нужно. Пока панель открыта, обновляй статы раз в ~0.25 с корутиной — реген и множитель урона от времени тикают постоянно.
- Escape при открытой панели должен сначала закрывать её, а не открывать паузу. Сейчас `PauseManager.Update` слушает Escape безусловно — у него есть `SetCanPause(bool)`, используй его.

### Раскладка

Рамка ~1200×700 в координатах канваса, по центру, полупрозрачный фон. Не на весь экран — полоски HP слева сверху и башня по краям должны оставаться видны.

Внутри:

- Шапка: заголовок и подсказка «Tab — закрыть».
- Слева сверху — сетка оружия, `GridLayoutGroup`, 4 колонки. Ячейка ~120×120.
- Слева снизу — сетка улучшений, 8 колонок, ячейка ~60×60 (их будет заметно больше).
- Справа колонка характеристик шириной ~260, отделена вертикальной линией.

`ShopPanel` в сцене уже использует `GridLayoutGroup` с `CellSize 300×300`, `Constraint = FixedColumnCount`, `ConstraintCount = 5` — можешь смотреть на него как на образец настройки.

### Ячейка

- Иконка из `def.icon`.
- Счётчик `×N` в правом нижнем углу. При `stacks == 1` **не показывай** — визуальный шум.
- Цвет рамки по тиру: 1 — серый, 2 — бирюзовый, 3 — фиолетовый, 4 — золотой и толщина рамки в 2 раза больше. Цвета вынеси в сериализуемый массив на компоненте панели, чтобы правились из инспектора.
- Ховер показывает тултип с названием и описанием.
- Клика нет — панель только для чтения.

### Панель характеристик

Собери значения из существующих полей и свойств. Ничего не пересчитывай своей формулой — бери готовое:

| Строка | Откуда |
|---|---|
| Здоровье | `PlayerHealth.CurrentHealth` / `MaxHealth` |
| Щит | `PlayerHealth.CurrentShield` / `MaxShield` |
| Реген | `healthRegenPerSecond` плюс бонус за недостающее HP, формула уже есть в `PlayerHealth.Update` — вынеси её в публичный метод `GetTotalRegen()` и используй в обоих местах, не дублируй |
| Шипы | `PlayerHealth.SpikesDamage` |
| Скорость атаки | `TowerAttack.fireRateMultiplier` |
| Множитель урона от времени | `UpgradePerTick.Instance.DamageMultiplier` |
| Урон от макс. HP | `UpgradesManager.damageFromMaxHealthPercent` |
| Урон при активном щите | `UpgradesManager.damageWhileShieldActivePercent` |
| Бонус золота | `GoldManager.GoldGainBonus` и `goldPerTick` |
| Бонус по типам урона | `UpgradesManager.damageTypeMultipliers[]`, индексируется `(int)WeaponDamageType` |

`WeaponDamageType` — enum из шести значений: `Magic, Piercing, Normal, Projectile, Heavy, Chaos`. Показывай все шесть строк, у неактивных ставь прочерк вместо `+0%` — так видно, куда ещё можно вложиться.

**Округляй всё, что выводится.** Множители показывай как `×2.30`, проценты как `+45%`, целые значения без дробной части.

## Часть 4. Тултип

`WeaponTooltip.ShowInternal` сейчас принимает `screenPos`, но игнорирует его — панель стоит фиксированно в правом нижнем углу под магазин. Для центральной рамки она будет перекрывать саму сетку.

Добавь позиционирование: панель появляется рядом с курсором со смещением, и клампится по краям экрана, чтобы не уезжала за границу. Учти, что у тултипа есть поле `offset`, оно уже сериализовано.

Проверь, что магазин по Q после этой правки не сломался — он использует тот же синглтон.

## Ограничения

- Только C#. Не редактируй `.unity`, `.prefab` и `.asset` файлы — сцену и префабы я соберу руками. Вместо этого в конце выдай список того, что нужно создать в редакторе: какие объекты, с какими компонентами, какие поля чему присвоить.
- Существующие публичные поля и их имена не переименовывай — на них завязаны ссылки в сцене.
- Комментарии в проекте на русском, придерживайся того же стиля.
- Никаких `Debug.Log` в коде, выполняющемся каждый кадр.
- Не используй `FindObjectsOfType` в `Update` — в проекте это уже узкое место в `TowerAttack.GetEnemiesInRange`, не усугубляй.

## Известная проблема, которую пока не трогай

У `GameCanvas` и `PauseCanvas` в `CanvasScaler` стоит референс `800×600`, хотя вся геометрия HUD рисовалась под `1920×1080` (у `MainMenuCanvas` референс правильный). Из-за этого HUD раздувается примерно в 2.4 раза на реальном экране. Это отдельный баг, чинится в инспекторе. Просто знай про него, когда будешь считать размеры панели: **проектируй в координатах 1920×1080**.
