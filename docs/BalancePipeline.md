# Балансовый пайплайн: Google Sheets ⇄ Unity

Источник правды по числам — таблица **«config ETS»** в Google Sheets. Ассеты в проекте
считаются производными: их числа перезаписывает импортёр. Правки чисел руками в инспекторе
живут только до следующего `Pull` — см. [«Как правильно менять числа»](#как-правильно-менять-числа).

Код тула: `Assets/Editor/Balance/`. Конкретные значения баланса по тирам — в [Balance.md](Balance.md).

---

## Команды меню `Tools/Balance`

### `Pull From Google Sheets + Import`
Основная команда. Скачивает все шесть вкладок в `Config/*.csv`, валидирует, стампит ассеты.

- Качает через gviz-эндпоинт по **имени** вкладки; нужен доступ «читатель по ссылке».
- Файлы на диск пишутся только когда скачались **все** вкладки — иначе в `Config/`
  осталась бы смесь новых и старых данных.
- Шапка каждой вкладки сверяется с ожидаемыми колонками (зачем — см. [Ловушки](#ловушки)).
- При **любой** ошибке валидации не меняется ни один ассет, все проблемы выводятся разом.

### `Import (Local CSV)`
То же самое, но без сети — из текущих `Config/*.csv`. Нужен, когда таблица недоступна
или когда правишь CSV локально, чтобы проверить гипотезу перед заливкой в таблицу.

### `Validate Only`
Только проверка `Config/*.csv`, не пишет ничего. Прогоняй перед коммитом.
Ловит: битые числа, дубли `id`/`asset_name`, тир вне 1..4, нулевые веса, ссылки на
несуществующие ассеты, апгрейды без записи в `UpgradeValueMap`, а также предупреждает про
ассеты в проекте, которых нет в таблице.

### `Export (Unity → Config CSV)`
Обратное направление: читает текущие значения из ассетов, префабов и `BalanceConfig`
и перезаписывает `Config/*.csv`. Дальше смотришь `git diff` — видно, где проект разошёлся
с таблицей. Если расхождений нет, файлы не трогаются («менять нечего»).

Колонки, которых в Unity не существует (`name`, `id`, `effect_1`, `effect_2`), экспорт
не выдумывает — переносит из текущего `Config/*.csv` по `asset_name`. Для ассета, которого
в CSV ещё нет, они останутся пустыми, и будет warning.

### `Copy Tab For Google Sheets/<вкладка>`
Та же выгрузка, но одной вкладкой в буфер обмена как TSV. Открываешь вкладку в таблице,
встаёшь на `A1`, `Ctrl+V` — данные лягут ровно по колонкам.

> **Почему не пишем в таблицу напрямую.** gviz, на котором держится `Pull`, работает только
> на чтение, а Sheets API требует OAuth или сервисного аккаунта — ключа в проекте нет.
> Поэтому «залив» сделан через буфер обмена.

## Куда попадает какая колонка

### `weapon` → ассеты `WeaponDefinition` (`Assets/Prefab/Weapon/<N>Tier/`)

| Колонка | Поле ассета |
|---|---|
| `asset_name` | **ключ связи** — имя файла ассета без расширения |
| `cost` | `price` |
| `damage` | `damagePerProjectile` |
| `attack_speed` | `fireRate` (выстрелов/сек) |
| `projectile_speed` | `projectileSpeed` |
| `tier` | `itemTier` (1..4) |
| `weight` | `weight` |
| `weight_increase_per_purchase` | `weightIncreasePerPurchase` |
| `max_weight_increase_purchases` | `maxWeightIncreasePurchases` |
| `damage_type` | `damageType` (`Magic`/`Piercing`/`Normal`/`Projectile`/`Heavy`/`Chaos`) |
| `name`, `id` | **в ассет не пишутся** — только в `balance.json` и для проверки уникальности |

### `upgrades` → ассеты `UpgradeBaseSO` (`Assets/Prefab/Upgrade/Tier<N>/`)

| Колонка | Поле ассета |
|---|---|
| `asset_name` | **ключ связи** |
| `cost` / `weight` / `tier` | `price` / `weight` / `itemTier` |
| `weight_increase_per_purchase`, `max_weight_increase_purchases` | одноимённые поля |
| `value_1`, `value_2`, `interval` | **через `UpgradeValueMap`** — см. ниже |
| `effect_1`, `effect_2` | **ни на что не влияют**: это текстовое описание для дизайнера |
| `name`, `id` | в ассет не пишутся |

`UpgradeValueMap` (в `Assets/Editor/Balance/BalanceAssetIndex.cs`) — ручная карта
«`asset_name` → в какое поле какого ассета класть `value_1/value_2/interval`».
Для композитов указывается класс дочернего ассета и, при необходимости, множитель `Scale`
(например, у t4-ультимейтов `valuePercentPerWeapon` хранится долей: `2` в таблице = `0.02` в ассете).

### Остальные вкладки

| Вкладка | Куда пишется |
|---|---|
| `enemy` | статы → `MeleeEnemy`/`MidrangeEnemy`/`RangeEnemy.prefab`; волны и сложность → `BalanceConfig.waves` |
| `boss` | статы → `BossMonster.prefab`; спавн и множители → `BalanceConfig.boss` |
| `shop` | цены разблокировок → `ShopUnlock_1/2.asset`, стартовое состояние → `ShopUnlockConfig.asset`, экономика → `BalanceConfig.shop` |
| `player_constant` | целиком в `BalanceConfig.player` |

`BalanceConfig.asset` лежит в `Assets/Resources/Balance/` и читается в рантайме через
`BalanceService` до `Awake` любых объектов сцены. Если его нет — игра работает на значениях
из инспектора и пишет warning.

## Как правильно менять числа

**Штатный путь — правка в таблице:**

1. Правишь значения в Google Sheet.
2. `Tools → Balance → Pull From Google Sheets + Import`.
3. Смотришь `git diff` по `Config/` и по ассетам, коммитишь **вместе** — CSV это снапшот
   того, из чего собраны ассеты.

**Если удобнее покрутить в инспекторе Unity:**

1. Крутишь значения в ассетах.
2. `Tools → Balance → Export (Unity → Config CSV)`, смотришь `git diff` по `Config/`.
3. `Tools → Balance → Copy Tab For Google Sheets/<вкладка>` → `Ctrl+V` в `A1` нужной вкладки.

> ⚠️ Инспекторные правки живут только до следующего `Pull` — он их перезатрёт.
> Выгружай в таблицу **до** того, как кто-то в команде сделает `Pull`.

## Как добавить новое оружие

1. **Ассет.** `Assets/Prefab/Weapon/<N>Tier/` → `Create → TD → Weapon`. Имя файла станет
   `asset_name` — оно же ключ связи с таблицей.
2. **Не-балансовые поля** заполни руками, импортёр их не трогает: `icon`, `bulletPrefab`,
   `localizedStringTable`, `nameKey`, `descriptionKey`, `targetingMode`.
3. **Строка в таблице**, вкладка `weapon`: `asset_name` = имя файла, уникальный `id`,
   `tier` 1..4, `weight` > 0, `damage_type` из списка допустимых. Пустые ячейки — ошибка,
   а не ноль.
4. **Добавь в пул магазина.** Открой `MainScene`, найди `ShopManager`, добавь ассет в список
   `availableWeapons`. **Без этого шага оружие не выпадет никогда**, а тул об этом
   не предупредит — см. [Ловушки](#ловушки).
5. `Pull From Google Sheets + Import`. В консоли не должно остаться warning
   «в проекте есть оружие X, а строки в таблице нет».

## Как добавить новый апгрейд

1. **Класс эффекта.** Если подходящего нет — новый класс-наследник `UpgradeBaseSO`
   с атрибутом `[CreateAssetMenu(menuName = "Upgrades/...")]`.
2. **Ассет.** `Assets/Prefab/Upgrade/Tier<N>/` → `Create → Upgrades → ...`.
3. **Строка в таблице**, вкладка `upgrades`: `asset_name`, уникальный `id`, `tier`, `weight`,
   `cost`, плюс `value_1`/`value_2`/`interval` — сколько нужно эффекту.
   `effect_1`/`effect_2` — текстовое описание, ни на что не влияет.
4. **Запись в `UpgradeValueMap`** (`Assets/Editor/Balance/BalanceAssetIndex.cs`):
   ```csharp
   ["MyUpgrade"] = new[] { ValueBinding.Self("value_1", "valuePercent") },
   ```
   Без неё импорт упадёт с ошибкой — так задумано, чтобы число из таблицы не потерялось молча.
5. **Добавь в `ShopManager.availableUpgrades`** в `MainScene`.
6. `Import`.

### Композитный апгрейд

1. Дочерние ассеты клади в `Assets/Prefab/Upgrade/CompositeComponent/<Имя>/` — эта папка
   исключена из индекса, чтобы дети не считались «забытыми в таблице».
2. Родитель — `Create → Upgrades → Composite` в `Tier<N>/`, дочерние ассеты в список `upgrades`.
3. В `UpgradeValueMap` используй `ValueBinding.Child`:
   ```csharp
   ["MyComposite"] = new[]
   {
       ValueBinding.Child("value_1", "SpikesBaseUpgrade", "valueFlat"),
       ValueBinding.Child("value_2", "HealPerEnemyHitUpgrade", "valueFlat"),
   },
   ```
   Второй аргумент — **имя класса** дочернего ассета, третий — имя сериализованного поля.
4. Если по каким-то причинам кладёшь детей не в `CompositeComponent/`, а рядом с родителем
   (как сделано у `MoreEnemy` и `NatureBlessing`), добавь их папку в `UpgradeExcludeFolders`
   в `BalanceAssetIndex.cs` — иначе они попадут в индекс как самостоятельные апгрейды.

## Как удалить оружие или апгрейд

Порядок важен: если удалить ассет первым, останутся битые ссылки.

1. **Убери из пула** — `ShopManager.availableWeapons` / `availableUpgrades` в `MainScene`.
2. **Проверь входящие ссылки** на ассет: поля `weightDecreaseUpgrades`, `weightIncreaseUpgrades`,
   `weightDecreaseWeapons`, `weightIncreaseWeapons` у других предметов, состав `CompositeUpgrade`.
   Удобно через `Find References In Scene` / поиск по GUID.
3. **Удали строку** из соответствующей вкладки таблицы.
4. **Удали запись** из `UpgradeValueMap` (для апгрейдов).
5. **Удали ассет** (для композита — вместе с дочерними в `CompositeComponent/<Имя>/`).
6. `Pull + Import`, консоль должна быть чистой.

> Если предмет надо временно вывести из выдачи, не удаляя, — достаточно убрать его из
> `availableWeapons`/`availableUpgrades`. Тул продолжит его стампить, но в магазине он
> не появится. Для совсем мёртвых ассетов есть список `UpgradeIgnore` в `BalanceAssetIndex.cs`
> (там сейчас `Hunting_old`).

## Ловушки

**Пул магазина живёт в сцене, а не в таблице.** `ShopManager.availableWeapons` и
`availableUpgrades` — списки в инспекторе `MainScene`. Импортёр и валидатор про них не знают:
ассет может иметь идеальные числа, строку в таблице и при этом никогда не выпадать.

**`itemTier = None` (`tier` = 0) тихо выкидывает предмет.** Вес такого предмета в рулетке
магазина — 0. Валидатор требует `tier` 1..4, так что через таблицу это не пройдёт, но
руками в инспекторе поставить можно.

**gviz врёт про несуществующую вкладку.** На неизвестное имя Google отвечает `200 OK`
и отдаёт **первую вкладку** таблицы, а не ошибку. Поэтому `Pull` сверяет шапку скачанного
CSV с ожидаемыми колонками. Если переименуешь вкладку в таблице — `Pull` упадёт с внятным
сообщением, а не затрёт CSV чужими данными.

**Дробные числа — через запятую.** Таблица в русской локали, в CSV лежит `0,5`.
Импортёр принимает и точку, и запятую, но разделитель разрядов (`1 234`) сломает значение
молча — не форматируй числовые ячейки как «с разделителями групп».

**Пустая ячейка — это ошибка, а не ноль.** Сделано намеренно: забытое значение не должно
превращаться в `0`.

**`weight` и `gold_for_enemy` валидируются как дробные, а пишутся целыми.** `4,5` пройдёт
проверку и молча станет `4`. Держи их целыми.
