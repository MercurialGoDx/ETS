# Баланс ETS: как это работает

**Источник правды — Google-таблица «ETS Config».** Все числа баланса правятся только там.
Ни инспектор Unity, ни файлы в проекте руками не правятся: следующий импорт перезапишет.

## Пайплайн

1. Гейм-дизайнер правит таблицу (6 вкладок: `weapon`, `enemy`, `boss`, `shop`, `player_constant`, `upgrades`).
2. В Unity: **Tools → Balance → Pull From Google Sheets + Import** — одна кнопка:
   скачивает вкладки, валидирует, при нуле ошибок записывает всё в проект.
   Без сети: **Import (Local CSV)** — импорт из `Config/*.csv`.
3. Проверить таблицу без записи: **Tools → Balance → Validate Only**.
4. Коммитятся вместе: `Config/*.csv` + `Assets/GameData/balance.json` +
   изменённые `.asset`/префабы + `BalanceConfig.asset` — одним коммитом `balance: ...`.

При **любой** ошибке валидации не меняется ни один файл; все проблемы выводятся разом
в Console с указанием вкладки и строки. Warnings не блокируют импорт.

Куда попадают данные: `weapon`/`upgrades` → прямо в ассеты (`Assets/Prefab/Weapon`, `Assets/Prefab/Upgrade`);
`enemy`/`boss` (статы) → префабы врагов; остальное → `Resources/Balance/BalanceConfig.asset`,
который игра читает через `BalanceService`. `balance.json` — снапшот для ревью, игра его не читает.

## Вкладка `weapon` (строка = оружие)

| Колонка | Тип | Диапазон | Что значит |
|---|---|---|---|
| `name` | текст | — | Русское название, только для людей. Игра не использует |
| `id` | целое | > 0, уникален | Постоянный номер. Схема: 1xx=тир1 … 4xx=тир4. Не переиспользовать |
| `attack_speed` | число | > 0 | Выстрелов в секунду. DPS = damage × attack_speed |
| `damage` | число | ≥ 0 | Урон за снаряд. 0 разрешён только Катапульте (её урон = 15% HP цели, задан на префабе снаряда) |
| `tier` | целое | 1–4 | Тир магазина |
| `weight` | число | > 0 | Вес в рулетке магазина. Шанс = вес / сумма весов доступных предметов |
| `cost` | целое | ≥ 0 | Цена в золоте |
| `damage_type` | текст | Magic, Piercing, Normal, Projectile, Heavy, Chaos | Тип урона — основа билдов: на него множатся апгрейды «+% к типу» и ультимейты |
| `projectile_speed` | число | > 0 | Скорость полёта снаряда (юниты/сек) |
| `weight_increase_per_purchase` | целое | любое | На сколько меняется вес после каждой покупки (может быть отрицательным — предмет будет выпадать реже) |
| `max_weight_increase_purchases` | целое | ≥ 0 | Сколько первых покупок меняют вес |
| `asset_name` | текст | — | **Служебное: имя ассета в Unity. Не менять и не переводить** |

## Вкладка `enemy` (одна строка значений)

| Колонка | Тип | Диапазон | Что значит |
|---|---|---|---|
| `damage_melee/mid/range` | число | ≥ 0 | Урон по башне за удар |
| `hp_melee/mid/range` | число | > 0 | Базовое HP (до множителя сложности) |
| `gold_for_enemy` | целое | ≥ 0 | Золото за убийство (любой обычный враг). Игра добавляет +1 за каждые 20 волн |
| `delay_per_wave` | число | > 0 | Секунд между волнами |
| `enemy_per_wave` | целое | > 0 | Врагов в волне (апгрейд «Больше врагов» добавляет % сверху) |
| `health_difficult_start` | число | > 0 | Базовый % роста множителя **здоровья** за волну — с начала забега |
| `damage_difficult_start` | число | > 0 | Базовый % роста множителя **урона** за волну — с начала забега |
| `growth_stage1_multiplier_health` | число | > 0 | Во сколько раз ускоряется рост **здоровья** после `time_difficult_stage1` секунд |
| `growth_stage1_multiplier_damage` | число | > 0 | Во сколько раз ускоряется рост **урона** после `time_difficult_stage1` секунд |
| `growth_stage2_multiplier_health` | число | ≥ stage1_health | То же для здоровья после `time_difficult_stage2` секунд |
| `growth_stage2_multiplier_damage` | число | ≥ stage1_damage | То же для урона после `time_difficult_stage2` секунд |
| `growth_stage3_multiplier_health` | число | ≥ stage2_health | То же для здоровья после `time_difficult_stage3` секунд |
| `growth_stage3_multiplier_damage` | число | ≥ stage2_damage | То же для урона после `time_difficult_stage3` секунд |
| `time_difficult_stage1` | число | > 0 | Секунда включения множителей stage1 (общая для HP и урона) |
| `time_difficult_stage2` | число | > stage1 | Секунда включения множителей stage2 (общая для HP и урона) |
| `time_difficult_stage3` | число | > stage2 | Секунда включения множителей stage3 (общая для HP и урона) |
| `speed_melee/mid/range` | число | > 0 | Скорость движения |
| `attack_interval` | число | > 0 | Секунд между ударами по башне |
| `hp_add_per_wave` | число | ≥ 0 | Фиксированная прибавка HP врагам за каждую волну (поверх множителя) |
| `damage_add_per_wave` | число | ≥ 0 | То же для урона |

Итоговые статы врага в волне N: `(база × множитель_сложности) + фикс_прибавка × N`. HP и урон растут
**раздельно**: у каждого свой базовый % за волну (`health_difficult_start` / `damage_difficult_start`)
и свой множитель ускорения на каждом пороге (`growth_stage1/2/3_multiplier_health` /
`growth_stage1/2/3_multiplier_damage`). Общие только пороги по времени (`time_difficult_stage1/2/3`).

Дальность атаки врагов задаётся кодом по типу (Melee 2.5 / Mid 6 / Range 10) и в таблицу не вынесена.

## Вкладка `boss` (одна строка значений)

| Колонка | Тип | Диапазон | Что значит |
|---|---|---|---|
| `additional_damage_boss` | число | ≥ 0 | Базовый плоский урон босса. Прибавляется после множителя и сам не масштабируется |
| `damage_boss` | число | > 0 | Множитель итогового урона обычного врага из `reference_enemy` |
| `hp_boss` | число | > 0 | Базовое плоское HP босса. Прибавляется после множителя и само не масштабируется |
| `hp_multiplier` | число | > 0 | Множитель итогового HP обычного врага из `reference_enemy` |
| `gold_for_boss` | целое | ≥ 0 | Золото за убийство |
| `speed_boss` | число | > 0 | Скорость движения |
| `attack_interval` | число | > 0 | Секунд между ударами |
| `attack_range` | число | > 0 | Дальность атаки |
| `spawn_interval` | число | > 0 | Секунд между спавнами босса (300 = каждые 5 минут) |
| `reference_enemy` | текст | melee, mid, range | Тип обычного врага, чьи итоговые HP и урон берутся за основу босса. Сейчас `melee` |

Итог при спавне:
`HP_ближнего = (hp_melee × сложность_HP) + flatHealthBonus`
`урон_ближнего = (damage_melee × сложность_урона) + flatDamageBonus`
`HP_босса = hp_boss + (HP_ближнего × hp_multiplier)`
`урон_босса = additional_damage_boss + (урон_ближнего × damage_boss)`

Босс берёт уже полностью рассчитанные статы типа врага из `reference_enemy` (сейчас `melee`), поэтому
`flatHealthBonus`/`flatDamageBonus` также попадают под босский множитель. `hp_boss` и
`additional_damage_boss` остаются плоской стартовой частью и ни на что не умножаются.
`damage_boss` — именно множитель, несмотря на историческое название. Отдельного
`damage_multiplier` в CSV больше нет.

| Колонка | Тип | Диапазон | Что значит |
|---|---|---|---|

| `tower_range` | число | > 0 | Радиус атаки башни |
| `volley_window_percent` | число | 0–1 | Доля интервала атаки, в которую размазывается залп стаков (0.5 = 50%) |
| `game_speed_1/2/3` | число | > 0 | Множители кнопок скорости игры |

## Вкладка `upgrades` (строка = улучшение)

| Колонка | Тип | Диапазон | Что значит |
|---|---|---|---|
| `name` | текст | — | Русское название, только для людей |
| `id` | целое | > 0, уникален | Схема: 11xx=тир1 … 14xx=тир4 |
| `tier` | целое | 1–4 | Тир магазина |
| `weight` | число | > 0 | Вес в рулетке |
| `cost` | целое | ≥ 0 | Цена (0 = бесплатный, напр. «Жадность», «Больше врагов») |
| `effect_1`, `value_1` | текст, число | — | Первый эффект и его величина |
| `effect_2`, `value_2` | текст, число | — | Второй эффект (только у композитных) |
| `interval` | число | > 0 | Для тиковых улучшений: период в секундах |
| `weight_increase_per_purchase` | целое | любое | Изменение веса за покупку («Золотая монетка» −5, «Золотая шахта» −7 — выпадают реже) |
| `max_weight_increase_purchases` | целое | ≥ 0 | Сколько покупок меняют вес |
| `asset_name` | текст | — | **Служебное, не менять** |

Смысл `value` определяется текстом `effect`: `+%` — проценты (10 = +10%), без знака % — плоская величина.
Колонки `effect_*` — подписи для людей; во что превращается число, определяет `asset_name`
(карта в `Assets/Editor/Balance/BalanceAssetIndex.cs`, `UpgradeValueMap`). **Добавили новое
улучшение — добавьте его и в карту**, иначе валидатор остановит импорт.

### Примечания к отдельным улучшениям

- **Жадность** (`Sacrifice`): −`value_1` HP, +`value_2` золота; фактическая выдача растёт
  на +5 за каждый уже купленный голд-апгрейд (зашито в ассете, поле `multGold`).
- **Больше врагов** (`MoreEnemy`): та же механика прибавки золота.
- **Блокирование** (`Block`): `value_1` — число стаков за покупку; проценты считает кривая
  с затуханием (см. `block_cap`).
- **Аура разложения** (`DegenAura`): урон/сек по площади = суммарный реген × `value_1`.
- **Сингулярность** (`DamageWhileShieldActive`): +`value_1`% ко всему урону башни,
  пока щит активен (не выбит и не в перезарядке). Без щита в билде бесполезна.
- **Ультимейты типов урона**: `value_1` = +% к типу, `value_2` = +% за каждое оружие
  этого типа у башни.

## Как добавить новое оружие

1. Создать `WeaponDefinition`-ассет в `Assets/Prefab/Weapon/<тир>Tier/` (ПКМ → Create → TD → Weapon),
   настроить в нём только «неотбалансное»: иконку, локализацию, префаб снаряда.
2. Добавить строку на вкладку `weapon` с `asset_name` = имя ассета и новым `id`.
3. Pull + Import.

Пока строки нет, импорт предупредит: «в проекте есть оружие X, а строки в таблице нет».

## Если что-то пошло не так

- **«вместо CSV пришёл HTML»** — таблица не расшарена: Настройки доступа → «Все, у кого есть ссылка» → Читатель.
- **«Не заполнены gid вкладок»** — в `Assets/Editor/Balance/BalanceImporter.cs` в `TabGids`
  проставить номер каждой вкладки (число после `#gid=` в URL браузера).
- Ошибки валидации — читать Console: формат `[вкладка!строка N] что не так`.
